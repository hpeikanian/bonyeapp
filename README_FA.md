# اپ مشتریان بنیه — نسخه توسعه ۰٫۱

این پروژه Flutter برای اندروید و مطابق قرارداد API بنیه ۵۳ نوشته شده است. کد اپ در همین مخزن است؛ کد سرور در پروژه جداگانه بنیه باقی می‌ماند.

## امکانات پیاده‌شده در کد

- رابط فارسی و راست‌به‌چپ؛ خانه، پت‌ها، باشگاه، آموزش و حساب.
- ورود با رمز یا OTP، ثبت‌نام و بازیابی با OTP؛ وابسته به تنظیمات واقعی سرور.
- نگهداری نشست در Secure Storage؛ Refresh تک‌درخواستی، چرخش توکن و ورود مجدد در پاسخ گم‌شده.
- ثبت و ویرایش پت، ثبت وزن و سابقه وزن، دریافت پیشنهاد غذا و برنامه از سرور و نمایش بازه مصرف.
- امتیاز، سطح و مزایا، اعتبار کوپنی و گردش، کوپن‌ها، پاداش‌ها، فعالیت، معرفی دوستان و تبدیل امتیاز.
- سوابق خرید سایت و شعب، ثبت و غیرفعال‌کردن یادآوری خرید، لینک خرید محصول در مرورگر.
- پروفایل، آدرس‌ها، رضایت دریافت پیام و نشست‌های فعال.
- مقاله‌های وردپرس، پادکست، پخش با کنترل سیستم/پس‌زمینه در صفحه پخش، سرعت، علاقه‌مندی، ذخیره سابقه و دانلود.

## اجرا

Flutter 3.29.3 و Dart همراه آن مبنای پروژه هستند. JDK 17 و Android SDK با platform و build-tools موردنیاز Flutter لازم‌اند. Android SDK 34/35، build-tools 34/35، NDK 27.0.12077973 و CMake 3.22.1 در این محیط نصب شده‌اند. JDK کامل 21.0.12.1 با checksum رسمی نصب شده است و با Gradle 8.10.2 سازگار است. برای نصب ابزارها از منابع رسمی Flutter و Android استفاده کنید؛ تأیید TLS یا checksum را خاموش نکنید.

```bash
cd /workspace/bonyeapp
flutter pub get --enforce-lockfile
flutter analyze
flutter test
flutter build apk --debug --target-platform android-arm64
```

API پیش‌فرض:
`https://bonye.pet/totallsystem/api/v1`

برای هاست آزمایشی مجاز، مقدار غیرمحرمانه را هنگام ساخت عوض کنید:

```bash
flutter run --dart-define=BONYE_API_BASE=https://YOUR-STAGING-HOST/totallsystem/api/v1
```

هیچ کلید مدیریتی، رمز دیتابیس یا کلید WooCommerce در اپ لازم نیست. فایل `pubspec.lock` باید پس از اولین نصب موفق وابستگی‌ها در مخزن نگه داشته شود؛ تولید و در پروژه نگه داشته شده است.

## وضعیت تأیید در این محیط

- Flutter 3.29.3، Dart 3.7.2، Android SDK 35 و وابستگی‌ها نصب شدند؛ pubspec.lock موجود است.
- `flutter analyze`: بدون خطا یا هشدار.
- `flutter test`: هر ۱۰ تست موفق؛ چرخش هم‌زمان نشست، پاسخ دیررس 401، پاسخ گم‌شده Refresh، حفظ کلید تکرار عملیات، خطای شبکه/پاسخ نامعتبر ثبت‌نام غیرفعال و جداسازی سابقه شنیدن در فایل‌های آفلاین پوشش داده شده‌اند.
- ۱۵ نمونه بدنه درخواست و ۲۶ اتصال مسیر/متد با OpenAPI تطبیق داده شدند.
- XML اندروید، ممنوعیت HTTP، غیرفعال بودن backup و تنظیم media playback بررسی شدند.
- Gradle wrapper از منبع رسمی نسخه 8.10.2 دریافت و SHA256 آن تأیید شد. checksum توزیع Gradle نیز pin شده است.
- ساخت APK آزمایشی ARM64 موفق شد؛ حداقل اندروید ۶ (API 23)، هدف API 35 و شناسه pet.bonye.customer است. امضای APK v2 با موفقیت تأیید شد و نتیجه نهایی در docs/validation.json ثبت می‌شود.
- درخواست فقط خواندنی به ریشه سایت و هر دو مسیر API از این محیط با پاسخ 503 پراکسی و متن upstream connection timeout مواجه شد. پاسخ خود برنامه دریافت نشده؛ این نتیجه به‌تنهایی نشان‌دهنده خرابی یا غیرفعال بودن API بنیه نیست.
- اتصال زنده، تست روی گوشی و پرداخت واقعی هنوز تأیید نشده‌اند.

## محدودیت‌های نسخه اولیه

- API فعلی ورود یکپارچه با وردپرس و Push delivery ندارد؛ خرید در مرورگر سایت انجام می‌شود.
- محتوای آموزشی از فهرست عمومی وردپرس می‌آید؛ پیشنهاد شخصی محتوا بر اساس پت هنوز به قرارداد سرور اضافه نشده است.
- پخش هنگام قفل گوشی با سرویس صوتی پیاده شده ولی روی دستگاه تست نشده. ترک صفحه پخش، پخش را متوقف می‌کند؛ مینی‌پلیر سراسری هنوز اضافه نشده است.
- فایل دانلودشده آفلاین پخش می‌شود. ورود، باشگاه و برنامه غذایی نیازمند اینترنت‌اند. همگام‌سازی خودکار صف آفلاین سابقه شنیدن هنوز وجود ندارد.
- برخی صفحات اولیه پت، محصول، آدرس و برنامه تا ۱۰۰ رکورد را نمایش می‌دهند. سوابق باشگاه و خرید صفحه‌بندی دارند؛ آموزش و پادکست هم صفحه‌بندی دارند.
- نمایش سوابق برخی بخش‌های باشگاه هنوز عمومی است؛ طراحی اختصاصی این کارت‌ها مرحله بعد است. تاریخ‌های داده فعلاً میلادی نمایش داده می‌شوند.
- حذف پت و آدرس هنوز در رابط اضافه نشده است. تأیید قوانین عضویت/حریم خصوصی، برند نهایی و امضای انتشار باید قبل از انتشار عمومی تکمیل شوند.
- ثبت‌نام، پیامک، داده انرژی واقعی/بازبینی دامپزشکی و مسیر صوت وردپرس باید در بنیه تنظیم شده باشند.

## آزمون اتصال و پذیرش

ابتدا `/meta` باید JSON با نسخه ۱ بدهد. سپس روی شماره و حساب آزمایشی متعلق به تیم، ورود، ثبت پت، برنامه غذایی، مشاهده باشگاه، خرید آزمایشی مجاز و ورود سفارش/امتیاز را کنترل کنید. تبدیل امتیاز یا خرید را بدون مجوز روی حساب واقعی اجرا نکنید.

پادکست: پخش/توقف، قفل گوشی، سرعت، دانلود، قطع اینترنت و برگشت به محل توقف را روی گوشی واقعی بررسی کنید. OTP واقعی و نگاشت حساب سایت جداگانه تأیید شوند.

ساخت debug برای آزمایش داخلی است. فایل release باید با کلید خصوصی مالک امضا شود؛ این پروژه کلید انتشار ندارد و release با کلید debug امضا نمی‌شود.
